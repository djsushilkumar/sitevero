# Sitevero — Elementor Specification (V3, V4, and Hybrid Engine)

## 1. Objective & Architectural Philosophy
Elementor represents a critical visual builder engine in WordPress. Rather than treating Elementor as a single static data format, Sitevero recognizes that Elementor has evolved across two major generations:
1. **Elementor V3 (Widget/Container Architecture):** Section-Column and Flexbox Container layouts with widget-based settings and inline-heavy CSS data models.
2. **Elementor V4 (Atomic Architecture):** Modular Atomic Elements (e.g., `e-div-block`, `e-flexbox`, `e-grid`), a CSS-first class-based styling system, variables (design tokens), and a flat DOM tree.
3. **Hybrid Pages:** Pages where legacy V3 elements and modern V4 Atomic Elements coexist within the same document tree.

Sitevero exposes **one unified capability** (`elementor.manage_page`) through the universal MCP tools (`sitevero_discover`, `sitevero_inspect`, `sitevero_execute`, `sitevero_rollback`). It does **not** expose fragmented version-specific tools like `elementor_v3_edit` or `elementor_v4_edit`. All version detection, parsing, normalization, routing, and compilation occur internally within Sitevero's Elementor Engine.

## 2. Universal Elementor Internal Processing Flow

```
                  Target WordPress Page
                            |
                            v
          [ 1. Model & Generation Detector ]
          - Inspect _elementor_data / document meta
          - Determine: "v3" | "v4" | "hybrid"
          - Check Free vs. Pro active status
                            |
                            v
          [ 2. Sub-Engine Parser & Normalizer ]
          - Parse raw JSON into Sitevero Normalized Schema
          - Flag unsupported elements safely as read-only
                            |
                            v
          [ 3. Pre-Execution Snapshot ]
          - Capture exact _elementor_data & meta (2MB limit)
                            |
                            v
          [ 4. Execution & Compilation ]
          - If target is V3: compile via V3Engine
          - If target is V4: compile via V4Engine
          - If Hybrid: compile each branch preserving untouched models
                            |
                            v
          [ 5. Document Save & Cache Clear ]
          - $document->save(...)
          - Clear CSS Cache (files_manager->clear_cache())
                            |
                            v
          [ 6. Internal Validation & Report ]
          - Re-read saved document & verify element integrity
```

### Critical Data Preservation Rules
- **No Forced Cross-Conversion:** Sitevero **never automatically converts V3 pages into V4**, and **never converts V4 pages into V3**. Unsupported conversion requests fail immediately with an explicit error.
- **Hybrid Preservation:** On hybrid pages, modifying a V3 container preserves existing V4 elements intact, and modifying a V4 atomic element preserves existing V3 widgets intact.
- **No Silent Data Destruction:** Any custom or unsupported element types encountered during parsing are preserved as opaque nodes in the document tree to prevent accidental layout stripping.

## 3. Elementor V3 Capability Specification

### 3.1 Supported Structural Models
- **Flexbox Containers:** Modern V3 layout containers (direction: `row` | `column`, wrap, justify, align, gaps).
- **Sections & Columns (Legacy):** Read-only inspection and widget editing within existing legacy sections/columns. (New layouts generated by Sitevero default to Containers).

### 3.2 Supported Core Widgets
- `heading`: Title text, HTML tag (`h1`–`h6`), link URL.
- `text-editor`: Rich content string.
- `image`: Attachment ID or URL, size (`thumbnail`, `medium`, `large`, `full`), link.
- `button`: Text, link URL, button type, size.
- `icon-box`: Title, description, icon name.
- `divider`: Style (`solid`, `dashed`), weight, color.
- `spacer`: Height (`px`, `vh`).

### 3.3 V3 Styling & Responsive Controls
- **Colors:** Text color, background color, border color.
- **Typography:** Font size, font family, font weight, line height, letter spacing.
- **Spacing:** Margin and padding (top, right, bottom, left with unit `px` or `rem`).
- **Alignment:** Left, center, right, justify.
- **Responsive Overrides:** Desktop (default), tablet, and mobile device-specific overrides (e.g., `typography_font_size_tablet`, `padding_mobile`).

## 4. Elementor V4 Atomic Capability Specification

### 4.1 Supported Atomic Elements
- `e-flexbox`: Flexbox layout container (direction, wrap, justify-content, align-items, gap).
- `e-grid`: Grid layout container (grid-template-columns, grid-template-rows, gap).
- `e-div-block`: Generic lightweight layout wrapper.
- Atomic Text & Heading elements: Semantic text blocks with direct HTML tag selection.
- Atomic Image elements: Responsive image nodes.
- Atomic Button elements: Interactive action triggers.

### 4.2 V4 Classes & Design Tokens (Variables)
- **Conceptual Boundary:**
  ```text
  Elementor V4 Variable / Design Token ≠ Arbitrary CSS Custom Property
  ```
  Elementor V4 manages design variables (tokens) through its structured Global Variables registry. Sitevero strictly interacts with Elementor's supported token schema and does **not** allow arbitrary CSS injection or ad-hoc CSS variable creation.
- **Global Classes:** Ability to assign and inspect reusable CSS classes applied to atomic elements (e.g., `classes: ["hero-card", "shadow-sm"]`).
- **Variables (Design Tokens):** Support for referencing and applying Elementor V4 design tokens bound to specific supported style properties (e.g., `variables: { "color": "e-var:brand-primary", "typography": "e-var:font-heading-xl" }`).
- **Styling System:** Class-first styling declarations compiled to Elementor V4's Atomic CSS schema.
- **Responsive & Interactions:** Responsive breakpoint overrides (Desktop, Tablet, Mobile) and supported basic hover/focus interaction states.

## 5. Hybrid Page Handling & Safe Model Detection
A page is classified as **Hybrid** when its `_elementor_data` structure contains both verified V3 elements and verified V4 Atomic Elements.

### Safe Model Detection Strategy
Model detection relies on verified Elementor V4 Atomic structures and data markers rather than naive substring matching. A node is never classified as V4 solely because its name begins with `e-`.

Supported detection outcomes:
- `"v3"`: Exclusively contains verified V3 sections, columns, containers, or standard V3 widgets.
- `"v4"`: Exclusively contains verified Elementor V4 Atomic Elements (`e-flexbox`, `e-grid`, `e-div-block`, atomic text/heading/image/button) and V4 schema markers.
- `"hybrid"`: Contains both verified V3 elements and verified V4 Atomic Elements.
- `"empty"`: No elements present in `_elementor_data`.
- `"unknown"`: Contains unrecognized, third-party, or unclassified element structures.

```php
public function detectGeneration(array $elements): string {
    if (empty($elements)) {
        return 'empty';
    }

    $hasV3 = false;
    $hasV4 = false;
    $hasUnknown = false;

    // Verified Elementor V4 Atomic layout & widget identifiers
    $verifiedV4Types = [
        'e-flexbox', 'e-grid', 'e-div-block',
        'atomic-heading', 'atomic-text', 'atomic-image', 'atomic-button'
    ];

    // Verified Elementor V3 layout & widget identifiers
    $verifiedV3Types = ['section', 'column', 'container', 'widget'];

    foreach ($elements as $element) {
        $elType = $element['elType'] ?? '';
        $widgetType = $element['widgetType'] ?? '';
        $isV4Structure = in_array($elType, $verifiedV4Types, true) 
            || (!empty($element['classes']) && isset($element['props']));

        if ($isV4Structure) {
            $hasV4 = true;
        } elseif (in_array($elType, $verifiedV3Types, true)) {
            $hasV3 = true;
        } else {
            $hasUnknown = true;
        }
    }

    if ($hasV3 && $hasV4) return 'hybrid';
    if ($hasV4 && !$hasUnknown) return 'v4';
    if ($hasV3 && !$hasUnknown) return 'v3';
    if ($hasUnknown && ($hasV3 || $hasV4)) return 'hybrid';
    return 'unknown';
}
```

### Safety & Data Preservation Rules
1. **Never Discard Unknown Nodes:** Unrecognized or third-party elements are preserved as opaque nodes in the document tree. Sitevero never strips or overwrites unknown nodes.
2. **Safe Mutation Failure:** If a mutation targets an element within an unknown or unverified structure that Sitevero cannot confidently parse, execution halts safely with `ERR_ELEMENTOR_UNSUPPORTED_STRUCTURE`.
3. **No Automatic Cross-Conversion:** Sitevero **never converts V3 elements to V4 or V4 to V3**.
4. **Isolated Branch Editing:** On hybrid pages, edits targeting V3 nodes are routed exclusively through `V3Engine`, leaving adjacent V4 branches untouched; edits targeting V4 nodes are routed through `V4Engine`, leaving adjacent V3 branches untouched.

## 6. Elementor Free vs. Pro Detection & Boundaries
- **Detection:** Sitevero inspects `defined('ELEMENTOR_VERSION')` and `defined('ELEMENTOR_PRO_VERSION')` during discovery.
- **Boundaries:**
  - Sitevero **does NOT bundle Elementor Pro** and does NOT require Pro.
  - If Elementor Pro is active, Sitevero detects it and allows **read-only inspection** of existing Pro elements (forms, popups, theme builder headers) so existing pages can be inspected without errors.
  - Sitevero **does NOT promise or support creation of Pro-only widgets** in MVP.
  - Unsupported requests for Pro-only creation fail gracefully with `ERR_ELEMENTOR_PRO_UNSUPPORTED`.

## 8. Explicitly Out of Scope
- Automated conversion of V3 pages to V4 or V4 to V3.
- Bundling or distributing Elementor Pro.
- Creating Elementor Pro-only widgets (Theme Builder, Popups, Form Builder).
- Third-party add-on widget packs (Essential Addons, HappyAddons, Crocoblock).
- Direct arbitrary CSS file writing.

---

## 9. Dependencies
- Elementor Core installed and activated.
- Free vs. Pro runtime detection.

## 10. Resolved Decisions
- *Decision 7.1: V3/V4 Architecture & Legacy Sections:* **RESOLVED.** Full architectural support for Elementor V3, Elementor V4 (Atomic Elements, classes, variables), and Hybrid coexistence. Existing page structures are preserved without forced migration.
